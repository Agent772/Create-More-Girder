## Unreleased
### Added
- Server config option `placement.createGirderPlacementSystem` (default `true`) to toggle between base Create's girder placement/update system and the CMG mechanic (sticky TOP/BOTTOM connectors + no beam→pole collapse) #163
- Russian translation (`ru_ru.json`) by savereks, mirrored from GitHub PR #18

### Changed
- Renamed the "Beam" family display names to "Girder" (e.g. "Andesite Beam" → "Andesite Girder") #165. Lang-only change: block/item IDs stay `*_beam`, so schematics, KubeJS scripts, datapacks, and existing worlds are unaffected. The Truss family keeps its name.

### Fixed
- Mimicked blocks losing colour trueness on copycat girders/struts/brackets. Blockbench-exported models with no `cullface` (e.g. Foxy's Mod glowing blocks) fell back to the particle texture, and layered glow-shell blocks collapsed to a single texture. The mimic sampler now scans the unculled quad list and draws each source layer per render type #167
- Copycat brackets rendering brighter than the source block, and copycat strut beams using the wrong mimic colour. Create's host models (shaft/cog, pipe) never consulted the bracket model's render types, so a translucent glow shell had no pass to blend on and was painted opaquely. The hosts now union the mimic's render types and the bracket routes each layer onto its own pass, matching the girder; strut beams now composite every sampled layer like the girder does — the base (core) layer renders on the beam's primary pass and each further layer (e.g. a semi-transparent glow shell) is alpha-blended over it on the translucent pass — and choose that primary pass by the mimicked block's nature: a light-emitting block (e.g. Foxy's neon concrete, authored entirely on the translucent layer with a semi-transparent glow shell) renders on an opaque alpha-tested pass so it reads as a solid neon block, while only genuinely glass-like blocks (translucent, non-emitting, no opaque layer) stay see-through #174
- Copycat strut beams rendering the mimic in a dull, un-glowing colour (e.g. lime instead of neon green) while copycat girders glowed correctly. Two causes: (1) beams applied only world light plus the block's `getLightEmission()`, but blocks that glow through a baked lightmap in their model quads (which the girder already samples) rather than through block-light emission report `getLightEmission()` `0` and left the beam world-lit; beams now combine that sampled per-face emissive lightmap into their vertex light on both render paths. (2) The remaining darkness was directional diffuse shading — Create's `SuperByteBuffer` (Fancy path) applies a per-normal diffuse darkening, and `putBulkData` (Fast path) applies the quad's baked shade, both of which dimmed the beam's side faces below the girder, whose emissive glow-shell faces are authored unshaded. Neither full diffuse, no diffuse, nor half-strength diffuse could match the girder, because the remaining difference was never lighting: the beam collapsed each face to the single topmost sprite drawn fully opaque, while the girder alpha-blends the semi-transparent glow shell over the opaque core (`pixel = shell×α + core×(1−α)`) — a colour no brightness tweak can reproduce. Beams now render the base layer plus alpha-blended overlay layers exactly like the girder (second cached mesh buffer on the Fancy path, second quad list on the translucent pass on the Fast path), and shade each layer with the source quad's own shade flag using the same per-face diffuse constants the chunk renderer applies to the girder (baked into vertex colours on Fancy, via the quad's shade flag in `putBulkData` on Fast) #174
- Mimicked blocks on CMG copycats (girder/bracket/strut) shading differently from base Create's copycats (e.g. copycat step) with the same material. Four deviations from Create's copycat pipeline, all removed: (1) light-emitting mimics (verified against Foxy's Mod glowing concrete, a `lightLevel(12)` block) were force-rendered fullbright with shading stripped, flattening every face to one uniform colour — Create's copycats emit the material's light into the world and render its quads with normal lighting/shading, so the sampler now keeps the authored lighting and only maxes the mimic's emission into the layer lightmap (paths whose host can't forward emission, e.g. brackets and contraptions, still glow); (2) the sampler stripped the source quads' authored `shade` flag whenever the source model disabled ambient occlusion — the authored per-quad `shade` and `hasAmbientOcclusion` flags are now carried onto the remapped quads; (3) the copycat models force-disabled model-level AO for mimicked faces — they now use vanilla AO behaviour like Create's copycats (non-mimicked struts keep their AO-off anchor rendering); (4) the mimic's authored layer geometry was flattened — every layer was repainted coplanar and full-size onto the copycat's quads, erasing the "glass contour" that OG copycats keep by cropping the material's *real* quads into the copycat box (`BakedModelHelper.cropAndMove`): Foxy's glowing blocks author an inset concrete core (0.5..15.5) under a full-cube glass shell, so OG copycats show a glass-only translucent ring framing every face plus depth parallax between the layers. Each sampled layer now records the source quad's inset from its face plane and its in-plane footprint, and the remapped chunk-model quads (girder, encased shaft, bracket, strut anchor) are cropped to it with the same clamp-plus-proportional-UV semantics as Create's `cropAndMove`; regions outside a layer's footprint draw nothing on that layer, recreating the contour ring. Each layer is recessed behind the painted face by its authored depth on *every* face (not only cube-boundary faces), so layer pairs never sit coplanar with differing footprints — that combination z-fights (flicker) because their interpolated depths differ by float rounding; slanted quads (the girder's diagonal lattice braces) are left uncropped for the same reason, since clamping their vertices would bend them out of plane. Strut beams keep flat alpha-compositing: their pole geometry spans between blocks and has no per-block face box, so a block-surface contour is undefined there #174

### Migration
- **The new default (`createGirderPlacementSystem=true`) makes CMG girders behave like base Create's metal girder.** Builds relying on sticky brackets or persistent horizontal beams will degrade lazily (brackets cleared, beams collapsing to poles) on their next neighbor update. To keep the old CMG behavior, set `createGirderPlacementSystem=false` in `serverconfig/createmoregirder-server.toml` **before** opening an existing world.
